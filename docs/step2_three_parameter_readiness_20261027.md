# 三参数方案可研究性核验

2026 年 10 月 27 日，香港时间。本文的“顺序 1、顺序 2”对应本聊天的项目进度表：先收尾真实诊断，再确认三个参数是否具备研究价值。

**顺序 1 已在工程诊断层面完成。顺序 2 的机制与空间核验也已完成：保留三个参数名称，采用已有的 early_compaction_v2 作为后续正式协议的候选空间。** 三个维度具备请求控制、自动压缩或保留边界的证据，性能收益与有益交互尚待正式实验检验。

**顺序 1 的验收依据**

原计划八项已全部执行，另有三项真实任务范围校准。逐项核对了八项原计划的结果或中断恢复记录，以及十一项任务的资源清理证明；闭环记录关联的六份证据文件哈希全部匹配。历史三项费用不完整记录保持未知，没有为凑齐结果而改写为零成本或正常完成。

“完成”指计划执行、结果归档和异常解释闭合，不表示十一项均成功通过判分，也不表示完整账单已经确证。下午 16:06 的参数核对是历史快照；其后两个 keepRecent 对照和三个新版范围对照已补齐。

当前另有独立的跨任务默认配置校准。它属于任务覆盖与预算测量，不能混作 IGBS 搜索或参数收益证据。

**保留的三个参数及候选取值**

| 参数 | 后续候选取值 | 原生默认 | 研究作用 |
|---|---|---|---|
| defaultThinkingLevel | low、medium、high | medium | 改变请求的推理档位，观察质量、费用和耗时 |
| compaction.reserveTokens | 16384、360000、375000 | 16384 | 在同一 400000 tokens 模型窗口中，改变自动压缩触发时机 |
| compaction.keepRecentTokens | 4000、10000、20000 | 20000 | 改变压缩时近期原始上下文的保留边界 |

仍为 3 × 3 × 3 = 27 个唯一配置；原生默认 medium / 16384 / 20000 在网格内。新版须显式指定 `live.space_profile=early_compaction_v2`，旧空间及 mock 路径保留。

reserveTokens 的数值较大，是为了在真实任务可达到的上下文长度触发压缩。锁定源码使用 `contextTokens > contextWindow - reserveTokens`：三个值对应严格超过 383616、40000、25000 tokens。这里没有把模型实际窗口从 400k 改小，也没有把 reserveTokens 当成摘要输出长度。

**行为证据及边界**

| 参数 | 已核验的依据 | 目前不能据此声称什么 |
|---|---|---|
| thinking | low / medium / high 均出现在 Pi 状态和真实请求 reasoning_effort 字段中 | 不能声称某档必然提高通过率，也不能精确推断供应商内部计算预算 |
| reserveTokens | 原始 RPC 日志中的两次 threshold 自动压缩均正常结束；375000 档在 27673 tokens 时压缩，360000 档在 42533 tokens 时压缩 | 不同随机轨迹不能单独证明压缩时机对成绩或费用的因果效应 |
| keepRecentTokens | 同一历史的独立真实摘要对照中，10000 与 40000 分别保留估算 10026 与 40026 tokens，保留边界不同；新版 4000 已用于两次真实任务压缩 | 同历史探针不是 SkillsBench 成绩；新版 4000 / 10000 / 20000 的全部质量差异尚未测量 |

两次真实任务压缩后的估算上下文分别为 1869 与 2883 tokens，均低于各自阈值，日志未出现中止、错误或重试。它们证明新版范围可以激活原生机制，不证明所有任务、所有配置都会发生压缩。

独立同历史探针使用明确标记的 128k 诊断上下文预算；真实任务和新版搜索空间保持原模型的 400k 窗口。两类证据分别使用，不能把压力探针包装成基准任务结果。

**空间与实现核验**

本次重新加载新版空间，27 个组合全部通过当前约束校验；四个现有空间测试全部通过，包括保留原默认、旧空间兼容、越界拒绝和准备过程不调用模型。四个上游 checkout 均匹配锁定提交且干净。

静态校验分别检查保留上下文与触发阈值的间隔，以及保留上下文与模型输出上限能否容纳于模型窗口。最紧组合为 reserve=375000、keepRecent=20000：扣除 4096 tokens 安全余量后只剩 904 tokens。校验通过不是动态长度保证；真实评测仍需记录摘要长度、压缩后上下文和重复压缩情况。

**进入正式比较前需要保留的研究边界**

- 参数机制可运行，不等于存在有益交互。早压缩与少保留、推理档位与上下文增长的关系，仍是待检验假设。
- 参数诊断中的任务判分均为 0，不能直接支持参数优劣排序。独立跨任务校准的结果应按其自己的样本和用途记录。
- 后续每次评测应保存推理档位、压缩次数、触发前后长度、保留边界、官方成功标签和费用。缺少压缩的轨迹不能被解释为 keepRecent 效应。
- 各方法必须使用相同的新版空间；诊断结果不能作为某个方法免费的初始化样本，空间和算法规则应在正式搜索前统一冻结。
- 保留 Pair-blind 消融并报告正交互权重实际触发次数。当前十配置草案在七点初始化后只有一次 pair、一次 single、一次 global，交互引导的机会有限；这属于下一步预算和研究问题的取舍，不能提前保证消融能得出显著差异。

本次核验支持继续采用三个参数开展研究，无需增加维度。正式实验次数、预算和配置优劣没有在此冻结，也没有因这次核验重新派发模型任务。
