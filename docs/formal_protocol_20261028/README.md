## 3. 方法、次数和选优规则

| 方法 | 验证配置数 | 每配置任务数 | 验证尝试数 | 冻结后留出尝试数 |
|---|---:|---:|---:|---:|
| Default | 1 | 8 | 8 | 16 |
| Random | 13 | 8 | 104 | 16 |
| SMAC BO | 13 | 8 | 104 | 16 |
| IGBS | 13 | 8 | 104 | 16 |
| Pair-blind | 13 | 8 | 104 | 16 |
| 合计 | 53 个方法内配置评测 | | **424** | **80** |

总计 **504 次任务尝试**，不是 504 次 API 请求；一个任务可能调用模型多次。各搜索方法在 27 点空间内不重复配置，方法间出现同一配置仍独立计费、独立执行。校准和环境准备不包含在上述次数内，单独报告。

采用 13 而不是旧版 10 的原因：IGBS 和 pair-blind 的前 7 组为默认、3 个单参数点、3 个双参数点；第 8–13 组执行两轮 `pair → single → global`。旧版只有一轮，交互引导机会太少。13 组给出 **两次计划参数对选择机会**，并不保证两次都会使用交互权重；证据不稳时仍均匀选择，无可用局部邻居时转全局。扩大次数的依据是算法结构，未依据正式比较结果选取。

Random 为未评测配置的随机抽样；BO 保持标准 SMAC 2.4.0，3 组初始化计入 13 组。IGBS 的 7 组初始化也完整计费。Pair-blind 保留相同初始化、单参数权重、候选选择和动作顺序，仅将参数对权重设为零。各搜索方法共有相同任务、空间、次数和美元额度；初始化设计不同属于算法本身的差异。

IGBS v1 固定：2000 次家族 bootstrap、0.95 半径分位数、实际差异阈值 0.05、至少 8 个家族、leave-one-group 稳定性至少 0.8。权重来自 `max(0, |delta| − radius − 0.05)`；正权重表示有稳定的交互幅度，**不等于正向收益**。Bootstrap 用于保守路由，不作为显著性检验。不得看过留出结果后调整这些门槛。

完整 8 任务 panel 才能反馈优化器、更新 incumbent。目标先最大化验证通过率；同分按该配置 panel 的已计量 USD、实测耗时、配置哈希依次破同分。官方 `reward == 1` 才记成功；例如 0.45 属于未通过，原始部分得分仍保存作辅助分析。Default 不做搜索，保留独立基线结果。

依据是 [八任务默认校准](../cross_task_calibration_completion_20261027.md)：已知请求费用 $1.03555110；其中自行车任务费用仅部分已知，完整总额仍为 null。原 $5 校准另留 $1 风险预留，其剩余可分配额不是账户余额。此次暂按已知 panel 费用 `c` 计算：Default 为 `ceil5(2c + 1)`；每搜索方法为 `ceil5(2 × 13c + 1)`；留出为 `ceil5(2.5 × c/8 × 80 + 1)`，得到 5 / 30 / 30。这些倍数是规划假设，不是统计上界。

按已知均值机械外推 504 次为 $65.24；搜索 2 倍、留出 2.5 倍情景为 $134.62。若每个 panel 都耗尽额外 $1 风险预留，单倍参考为 $128.24。上述基数含不完整超时费用，留出任务也未测，**执行前必须完成计量处理并重新核价**。旧 408 次 / $135 仅保留为历史规模参考，不允许运行中按成绩切换协议。

串行时间按当前冷/热混合环境均值机械外推约 56.2 小时，二倍情景约 112.3 小时；均非工期承诺。所有任务保留原生 build / agent / verifier 时限；每搜索方法累计活动时间上限为 250380 秒（13 × 19260）。当前控制器也把这个值用于 Default，但 Default 只派发一组。原生各阶段的名义合计约 337 小时，清理可能另加时间，这个合计不是新增的总计时器或保证上界。先一致准备环境镜像层，准备耗时另报，不能仅为某方法预热任务或改依赖。

失败处理事先固定如下：

| 情况 | 处理 |
|---|---|
| 官方失败、部分得分、超时；费用和用量完整 | 占一次尝试，记未通过，实际费用计入预算，保留失败原因 |
| 环境失败且可证明未派发模型 | 记未通过并占一次尝试；只有确认未派发时才记零模型费；不自动补跑 |
| 用量缺失、费用未知、计量错误、清理或系统性问题 | 停止整个比较，保留 null 和原始证据，不能把未知改成零或把预留当实际成本 |
| 某方法次数、USD 或活动时间达到上限 | 停止该方法；其他方法遵循现有额度，无自动预算转移；任何方法未完成就不冻结最终赢家 |
| 中断、残缺 panel、优化器异常 | 保留已发生费用与日志，不免费重启、不丢弃失败重选题；未完成比较只报告诊断状态 |

目前普通 HPO 的缺失计量即停止规则保持生效。校准阶段的一次专用风险预留恢复不能直接用于正式 HPO。启动前需解决超时/取消请求的完整计量，验证正常超时可以可靠落账；若必须引入保守计费政策，应先另行修改协议、实现和预算，原始未知费用仍保留。

## 5. 冻结与最终评测

流程固定为：完成 424 次验证 → 审计全部完整 panel、费用和派发记录 → 同时冻结 Default 与四个赢家 → 80 次独立留出 → 对账与报告。

冻结保存运行 manifest、summary、events 哈希，以及模型、运行时、三参数设置、种子和分割哈希。任何方法残缺、费用未知、未结清派发或源文件不一致均不能进入最终评测。独立入口验证一次性冻结标记；同一冻结不能重复启动留出。即使不同方法选出相同配置，仍各执行自己的 16 项并分别计费；不得用测试较好的那一次回填其他方法。

留出每任务每冻结配置只尝试一次，固定分母 16；官方失败占分母。若留出未完整执行，明确标记 incomplete，未执行任务保持未知，不能把已有成功数除以较小分母冒充最终 pass@1。不能因某配置在留出失败而重跑、换配置或重新搜索。
