**2. 前四页现在可以怎样写**

**第 1 页：问题与假设。**公开配置会改变推理和上下文管理行为，默认配置未必适合所有任务，而穷举评测会消耗费用。研究目标是在固定源码、模型和有限预算下，通过验证集选择配置，再在独立任务上检验。检验 IGBS 相对 Random/SMAC 的搜索效率；本轮不检验交互引导相对 pair-blind 的独立贡献。

27 个配置保留原默认。较大的 reserve 值用于在任务可达到的上下文长度触发压缩；reserve 不是摘要长度。早期 mock 空间的取值不同，不能把旧表直接用于正式实验页。证据见 [三参数核验](step2_three_parameter_readiness_20261027.md)、[诊断闭环](pi_diagnostic_completion_20261027.md)。

**第 3 页：方法用流程图解释。**

建议图：`默认＋3 个单参数点＋3 个双参数点 → 同任务局部对照 → 稳定性权重 → pair/single/global 候选 → 完整验证 panel → 更新历史与最佳配置`。

一句话：参数一起变化的效果可能不同于单独变化效果之和，IGBS 用已观察到的局部对照决定下一步优先探索哪个参数块；证据不足时按既定规则回退。Pair-blind 保留相同初始化与动作顺序，移除参数对引导，用来检验引导本身的贡献。

贡献定位是针对固定 Harness 小型离散空间实现并检验一种外部配置搜索策略。SMAC 的随机森林本身也能表达交互；不能把“BO 不支持交互”当创新理由，也不声称首次提出交互优化。

**第 4 页：用一张表讲清公平性。**

- 固定 Pi、模型、任务、Skills；全部方法使用同一 27 点空间。
- 8 个验证任务、8 个留出任务；按家族隔离的方案不是官方划分或完整语义去重认证。
- Default 测一个配置；三搜索方法各 10 配置，初始化完整计入预算。
- 计划 248 次验证＋32 次留出＝280 次任务尝试，一个任务可包含多个 API 请求。
- 已授权 $60 分阶段额度；不能称为实际花费，也不保证跑满计划次数。
- 全部赢家冻结后再留出；失败保留且占次数，费用未知时停止比较。
- 一个搜索种子、小样本探索性比较；不承诺跨种子稳健或统计显著优于基线。
