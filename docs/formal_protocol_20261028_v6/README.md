## 新证据与固定计量

修复后受控自行车触发 20 秒 watchdog、wall time 89.45 秒，3/3 请求取得完整回执，总 $0.03214575，与独立 key usage 增量一致。最后请求在客户端超时后仍完成，供应商 `cancelled=false`；不得把客户端超时等同供应商取消。这个实例验证超时后计量，不是按原生 900 秒的任务成绩。首轮受控诊断仍有一笔无 ID，保持 null 和预留。

封存请求账本、隐式 SDK/router retries=0、在 Responses→Chat 转换前捕获 ID；代理断开后最多 45 秒等待既有回调。账本完整且参数/模型、worker 收尾、清理均通过才可结算。终态回执 404 可延迟到达：只对 404 做 5/15/30/60/60 秒退避，整体最多 180 秒，单次查询最多 15 秒；401/403 停止。查询/等待属于计量时间，不延长 agent 作答。总 wall time包括这些开销。

新退避自动逻辑已用离线回归验证；完整真实对账实例采用分开的只读补账。若未来回执仍不完整，正式比较继续停止。源码未改动固定上游；所有变化在项目层。没有 generation ID 的历史请求不能用修复倒推。详见 [验收记录](../completion_acceptance_20261028.md)。
