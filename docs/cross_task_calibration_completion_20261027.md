原来的 600 秒 build、600 秒 agent 和 600 秒 verifier 时限未改，任务依赖和上游源码未改。旧超时的缓冲构建日志未保留下来，所以只能确认“通过预备原生镜像层恢复执行”，不能声称已经精确定位到旧日志中的某个包或网络请求。将来清理 Docker 缓存后需要重新准备；正式各方法应采用一致的环境准备策略，准备耗时另报。

## 第 3 步：建议的正式规模

- 固定 **8 个验证任务、16 个独立留出任务**，不根据本次得分或费用替换任务；沿用已审计的任务家族隔离，原留出池中 6 个相关任务继续排除。该审计基于元数据，不是完整语义去重认证。
- 方法：Default、Random、BO、IGBS、pair-blind。Default 1 组配置；四个搜索方法各 **10 组配置**。BO 初始化 3 组；IGBS 和 pair-blind 初始化 7 组、适应性选择 3 组。
- 搜索种子 **20261027**、评测种子 **6203**、调度种子 **42**。一个搜索种子用于探索性比较，不作跨种子稳健性声明；供应商随机性不受这些种子控制。
- 正式验证：8 + 4×10×8 = **328 次**；冻结 Default 与四个赢家后，5×16 = **80 次**独立留出；合计 **408 次**。本次校准不计入这 408 次，也不免费提供给优化器。
- 顺序固定为验证搜索 → 核验完整 panel → 一并冻结赢家 → 独立留出。测试结果不回传优化器；不完整或费用未知的验证实验不能冻结赢家。
